# AA refresh quota guard

Approved scope: keep free source data current without exhausting upstream quotas. Existing credentials stay server-side and unchanged.

1. Add a service-only fixed-window state and leased refresh RPCs. The upstream reset timestamp, not UTC midnight, defines the window. Reserve each request before fetching, leave ten upstream requests available, cap this app at ninety requests per window.
2. Record limit/remaining/reset and Retry-After after every response, including failed tier probes. Refuse concurrent refreshes, exhausted budgets and active backoff.
3. Keep complete-page/index-version validation and last-good data; finish or release the lease on success/failure.
4. Test isolated database boundaries and a fake HTTP/RPC client. Deploy the migration and Edge Function, preserving JWT verification, then change the existing cron from twelve to four hours. Do not change the live freshness claim before deployment is verified.
5. Verify the next scheduled run and its quota receipt. No new credentials, paid tier, unrelated data deletion or public write access.
